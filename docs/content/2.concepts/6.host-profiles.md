# Host profiles

Claude and ChatGPT don't implement quite the same contract on top of the shared MCP Apps
spec. `@mcpapps/protocol` encodes the difference as data — `HOST_PROFILES` — instead of
scattered comments, so both the server's vendor-compat mirroring and `mcpapps audit` stay
in sync with it.

```ts
import { HOST_PROFILES } from "@mcpapps/protocol";

HOST_PROFILES.claude.delivery.requiresSingleFile;  // true
HOST_PROFILES.chatgpt.cspKeyMap;                    // { connectDomains: "connect_domains", resourceDomains: "resource_domains" }
```

## Claude

- **Single-file delivery.** Claude serves exactly one self-contained
  `text/html;profile=mcp-app` resource — no sibling assets. This is why Flutter builds fold
  into one document (`buildFlutterComponent({ inline: true })`) rather than shipping a
  `basePath` + asset map. A component whose only body is `basePath` cannot be delivered to
  Claude — `mcpapps audit --host claude` fails on this.
- **No documented byte-size limit** exists today — `HOST_PROFILES.claude.delivery.maxHtmlBytes`
  is intentionally left unset rather than guessed. If Claude's actual behavior surfaces a real
  limit, encode it there and the audit will start enforcing it.
- Consumes `_meta.ui.csp`'s four buckets as-is; no vendor CSP mirror key.

## ChatGPT

- **Vendor `_meta` mirroring.** With `compat: true` (or `compat: ["chatgpt"]`) on `defineApp`,
  the server mirrors the spec `_meta.ui` block into `openai/outputTemplate`,
  `mcpui.dev/ui-resource-uri`, and a snake_case `openai/widgetCSP`.
- **Only two of the four CSP buckets have a known mapping**: `connectDomains →
  connect_domains` and `resourceDomains → resource_domains`. `frameDomains` and
  `baseUriDomains` are **not** mirrored — `HOST_PROFILES.chatgpt.cspKeyMap` simply omits
  them, and `mcpapps audit --host chatgpt` warns if a component declares either while
  targeting ChatGPT, since that declaration won't reach ChatGPT's client.
- No single-file requirement — a `basePath`/asset-map component is fine.

## Auditing against a specific host

```bash
mcpapps audit --host claude     # only Claude's checks
mcpapps audit --host chatgpt    # only ChatGPT's checks
mcpapps audit --host all        # both (default)
```

The runtime layer (`--runtime`, a real headless-browser pass) is host-aware too: the CSP
buckets it treats as "declared" when checking for undeclared-origin drift come from the
same `cspKeyMap` — a `chatgpt`-only run doesn't expect `frameDomains`/`baseUriDomains`
traffic to be pre-declared the way a `claude` run does, since Claude has no dropped-bucket
gap.

## Extending this

Adding a new host (or a new fact about an existing one) means editing exactly one place —
`packages/protocol/src/host-profiles.ts` — and both the server's compat mirroring and the
CLI's audit pick it up automatically; neither hardcodes a host's specifics itself.
