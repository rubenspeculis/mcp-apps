# Sydney events

`sydney` is a Vue-renderer MCP App that searches Australian Tourism Data Warehouse (ATDW)
event listings and renders them as a card grid with drill-in detail. It was built against the published
`@mcpapps/*` packages rather than the workspace, and it exercises parts of the framework the
examples do not: a real upstream API, remote images under CSP, two-screen navigation, and a
secret.

## Shape of the app

| Piece | Detail |
| --- | --- |
| Tools | `search_events`, `get_event_details` (`sydney/src/app.ts`) |
| Components | `EventGrid.vue` → `ui://sydney/search-events`, `EventDetail.vue` → `ui://sydney/get-event-details` (`sydney/mcpapps.config.ts`) |
| Upstream | ATDW Atlas API, `cats=EVENT&st=NSW&rg=Greater Sydney` (`sydney/src/lib/atdw.ts`) |
| CSP | `resourceDomains: ["https://assets.atdw-online.com.au"]` for card and hero images |
| Host compat | `compat: true`, so ChatGPT also gets `openai/widgetCSP` |
| Runtime | Node via `mcpapps serve`, Cloudflare Workers via `wrangler` (`sydney/src/worker.ts`) |
| Packages | pinned to published `@mcpapps/*@0.1.2` |

Both tools are fully typed end to end: `searchEventsInput`/`searchEventsOutput` live in
`sydney/src/shared/schemas.ts`, the server's handler returns exactly that output type, and
the component reads `useToolResult<"search_events">()` with inference from the same
schemas. Nothing in the app restates the wire shape.

## What held up

- **Typed hooks carried the whole app.** `useCallTool("get_event_details")` resolves with
  the schema-inferred output, so the grid renders its detail view from a local ref without
  restating any shape.
- **Component CSP was enough for remote images.** Declaring `resourceDomains` in
  `mcpapps.config.ts` covered ATDW's image host without per-host branching.
- **`compat: true` cost nothing.** One flag emits the ChatGPT metadata beside the MCP Apps
  metadata, so one build serves both hosts.
- **The emulator got close, and the contract covered the rest.** The gaps it cannot express
  (a host refusing to switch components, for instance) surfaced in a real host – see below.

## What bit us

### A tool call does not switch the host UI

Clicking a card called `get_event_details`, got the data back – and the host kept showing
the grid. Component-initiated `tools/call` is a data request, not navigation; the host does
not swap the iframe to the called tool's `ui://` resource.

The fix was in-component routing: `EventGrid.vue` holds `detailData` and renders the detail
view itself, with a local back button. The tool call is just how it fetches. See
[the host bridge](/concepts/the-bridge#tool-calls-do-not-switch-the-host-ui) for the
general rule and the pattern.

A related detail: the grid calls `search_events` from `onMounted` when no tool result has
arrived yet, so the component is still useful when the host renders it without a prior
invocation (live-reload replay, direct resource access).

### Style against the container, not the viewport

The iframe's width is chosen by the host and can be much narrower or wider than any browser
window. Media queries get this wrong. `EventGrid.vue` sets `container-type: inline-size` and
uses `@container (min-width: 480px)` / `(720px)` for the 1→2→3 column grid, plus `cqi` units
for padding and type scale. The same component then works in a chat sidebar and a wide
canvas.

### The emulator does not load `.env` for you

`mcpapps dev` imports your app in-process, so it sees the environment of the CLI process and
nothing else. `node --env-file` does not apply either, because you invoke the `mcpapps` bin
rather than node. The working incantation:

```json
"dev": "export $(grep -v '^#' .env | xargs) && mcpapps dev"
```

For the deployed Worker the secret is set once with `wrangler secret put ATDW_API_KEY`. See
[the dev emulator](/guides/emulator#environment-variables).

### Secrets have to be injected per request

`defineTool` handlers close over module state, which is fine for a module-scope read under
Node and wrong under Workers, where the binding arrives on `c.env`. `sydney/src/worker.ts`
resolves the Hono way — a middleware that reads `c.env.ATDW_API_KEY ?? process.env.ATDW_API_KEY`
and pushes it into the API client before every request:

```ts
hono.use('*', async (c, next) => {
  const key = (c.env as { ATDW_API_KEY?: string })?.ATDW_API_KEY ?? process.env.ATDW_API_KEY ?? '';
  setAtdwApiKey(key);
  await next();
});
```

### Map the upstream API at the boundary

Output schemas are strict (`additionalProperties: false`), so a handler must return exactly
the declared fields – passing an upstream object through fails validation. That turned out
to be a feature: ATDW's `/products` (search) and `/product` (detail) endpoints return
different shapes for the same concept, and writing the mappers forced the difference into
one place.

Concrete mismatches worth knowing if you consume ATDW:

- Search returns `productImage` as a single URL string; detail returns `multimedia[]` with
  the same image at several sizes, so dedupe by `multimediaId`.
- Address fields mix conventions: snake_case (`address_type`) in search, camelCase with
  `attributeIdAddress === 'PHYSICAL'` in detail.
- Rates are strings, and free entry is `freeEntryFlag` as either `1` or `"1"` – compare loosely.
- Recurring events carry `frequencyStartDate`/`frequencyEndDate` instead of `startDate`/`endDate`.

### Parse the response encoding, not just the body

ATDW responds in **UTF-16LE**. `await res.json()` fails; the client reads
`await res.arrayBuffer()` and decodes with `new TextDecoder('utf-16le')` before parsing.
Any non-UTF-8 upstream needs the same treatment.

### Guard the formatting, not the schema

Dates are legitimately empty for some listings, and `new Date('')` renders "Invalid Date".
`EventGrid.vue` returns an empty string for blank dates rather than relying on the type
system – the field is a `string`, and `""` is a valid one.

## Checklist for the next app

- Put every screen in one component unless you *want* the host to own navigation.
- `container-type: inline-size` and `cqi` units from the first commit.
- Return exactly the declared output schema; map the upstream API in one module.
- Declare `resourceDomains` for every remote image or font origin.
- Export env vars before `mcpapps dev`; inject secrets per request, not at module scope.
- Run `mcpapps audit` against a build before trusting a new host.
