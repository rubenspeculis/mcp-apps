# Field reports

Framework documentation describes intended use. Field reports record what happened when a
real app pushed against the edges: which parts held up, which host behaviours the spec
leaves to the implementation, and which gaps are still open.

Each report names the app, the specific symptoms, and the fix, so the next person hitting
the same wall has somewhere to land. Where a lesson belongs in the framework rather than in
one app, it is also folded into the relevant guide – the report links to it.
